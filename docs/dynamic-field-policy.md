# 全类目动态字段策略

系统不维护一份固定的阿里字段清单。每个商品确认叶子类目后，必须重新读取
`alibaba.icbu.product.schema.get` 返回的实时 Schema，并以 Schema 的字段、选项、
`requiredRule`、`disableRule`、条件依赖和 `valueAttributeRule` 作为唯一提交依据。

## 字段责任

| 责任 | 处理方式 |
| --- | --- |
| 系统自动 | 图片银行 URL/ID、店铺默认值、已保存的商品事实、格式转换和条件清理 |
| AI 建议 | 标题、关键词、卖点、可由图片证实的属性和图片分类建议；必须经过用户确认 |
| 用户确认 | 类目、价格模式、价格、库存、尺寸、重量、物流、认证和任何交易承诺 |
| 阿里页面 | 公开 ICBU API 未可靠支持的新版结构化详情分类 |

## 页面行为

- 实时 Schema 的全部可编辑字段都有入口；平台托管、只读和隐藏字段不要求用户填写。
- 必填字段决定是否可以创建草稿。
- 非必填字段永远只显示为建议或可选，不阻塞创建草稿。
- 条件字段只在依赖条件生效时进入待填写清单；切换价格模式时清理失效字段。
- 每个字段显示来源、责任、当前状态和阿里规则提示。
- 可选字段存在未处理项时自动展开，避免“字段存在但用户找不到”。

## 数据复用

- 商品级真实事实（价格、库存、SKU、尺寸、重量、包装、产地和认证）只复用于同一商品，首次使用需确认。
- 店铺级默认资料（公司介绍、售后、币种、单位、仓库和运费模板）可自动带入，但商品页仍可覆盖。
- 类目变更后丢弃旧类目字段，只保留可证明仍有效的通用事实，并重新读取 Schema。

## 提交前校验

创建草稿前重新获取当前类目 Schema，校验必填值、选项值、条件字段、价格模式冲突、
图片银行来源和字段属性；校验失败必须定位到具体字段，不得只显示笼统错误。
