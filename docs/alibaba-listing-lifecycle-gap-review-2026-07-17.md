# Alibaba 国际站上品全生命周期与系统差距记录

记录日期：2026-07-17  
状态：第一阶段已于 2026-07-17 落地并进入线上验证  
范围：从店铺授权、商品创建到审核、质量优化及发布后维护  

## 1. 记录目的

本记录用于保存 Alibaba 国际站官方上品流程调研结论，并对照当前上品台实现，明确后续优化重点。

核心结论：当前系统对“选择类目、实时 Schema、补齐字段、图片银行、创建草稿和人工确认发布”的主链路覆盖较完整。下一阶段的主要风险不再是维护一套固定字段时发生遗漏，而是正式发布后的审核状态、结果不确定处理、合规门禁、质量优化和持续运营尚未形成完整闭环。

## 2. Alibaba 官方上品生命周期

```mermaid
flowchart LR
    A["授权与店铺能力"] --> B["确认真实叶子类目"]
    B --> C["获取实时发布 Schema"]
    C --> D["准备图片与视频素材"]
    D --> E["填写商品、交易、物流与合规信息"]
    E --> F["Schema 校验"]
    F --> G["创建草稿"]
    G --> H["草稿回读与人工确认"]
    H --> I["正式提交发布"]
    I --> J["平台审核"]
    J --> K["查询质量分与展示状态"]
    K --> L["更新、库存同步与上下架维护"]
```

### 2.1 授权和店铺能力

- 确认店铺授权、访问令牌和商品相关接口权限有效。
- 读取店铺可发布类目、商品分组、图片银行、仓库、运费模板等真实配置。
- 区分当前类目是否支持询盘品、在线批发下单品或两者都支持。

### 2.2 确认最终叶子类目

- AI 只推荐候选类目。
- 最终类目必须来自 Alibaba 实时类目树，并由商家确认。
- 只有叶子类目可以发布商品；类目决定后续全部字段和动态规则。

### 2.3 获取实时 Schema

- 调用 Alibaba 商品发布 Schema 接口获取当前类目的真实表单规则。
- 解析字段类型、枚举、复合组、重复组、条件必填、只读规则和父子联动选项。
- 不使用一套写死的通用字段表代替实时 Schema。

### 2.4 准备媒体素材

- 主图、详情图和 SKU 图片上传 Alibaba 图片银行后，再将平台 URL 写入 Schema。
- 主图顺序、图片清晰度、主体占比和商品一致性影响商品质量。
- 主图视频和详情视频属于增强项；只有当前 Schema 明确要求时才应阻止创建草稿或发布。

### 2.5 填写商品信息

| 信息组 | 典型字段 | 合法来源 |
|---|---|---|
| 内容信息 | 英文标题、关键词、卖点、详情描述 | AI 起草，人工确认 |
| 商品事实 | 品牌、型号、材质、尺寸、重量、包装、原产地 | 商家、ERP、可信资料 |
| SKU 与交易 | SKU、价格、阶梯价、MOQ、库存、交期、样品规则 | 商家、ERP、报价系统 |
| 物流履约 | 仓库、库存地点、发货港、运费模板、包装尺寸 | 店铺配置、ERP、物流系统 |
| 合规信息 | 认证、商标、专利、品牌授权、HS Code | 商家与真实证明文件 |

AI 不得猜测或自动确认价格、库存、材质、尺寸、重量、认证、品牌授权等经营和合规事实。

### 2.6 草稿、回读和正式发布

- 先创建 Alibaba 草稿，不直接正式发布。
- 使用返回的草稿商品 ID 回读平台实际保存的数据。
- 展示提交值与平台保存值的差异，要求用户确认。
- 只有用户显式确认后，才能调用正式发布接口。

### 2.7 审核和发布后维护

- 正式发布接口成功只代表平台接受请求，不等于审核通过。
- 需要持续查询商品真实状态、审核失败原因和产品质量分。
- 审核通过后仍需支持商品更新、库存同步、上下架、类目迁移和 Schema 变化检查。

## 3. 当前系统覆盖情况

### 3.1 已覆盖

- 店铺 OAuth 授权和通用店铺配置。
- AI 图片分析、标题、关键词、卖点及类目候选建议。
- Alibaba 真实类目树、叶子类目确认和类目发布能力读取。
- 实时 Schema 获取、解析、动态字段渲染和条件校验。
- AI 候选、用户确认、业务系统和店铺默认值的来源门禁。
- SKU、价格、MOQ、库存、包装和物流动态字段。
- 图片银行上传和平台图片 URL 写入。
- 草稿创建、草稿回读、差异确认和正式发布确认。
- 后端已具备商品详情、质量分、库存更新、商品更新和上下架接口。
- 浏览器端工作台恢复，可避免普通刷新或误触页面后立即丢失当前进度。

### 3.2 判断

当前系统可以通过实时 Schema 避免大部分“某个类目新增字段但系统没有入口”的问题。后续不应继续堆叠固定字段，而应围绕 Schema 任务转换、状态闭环和异常恢复优化。

## 4. 后续优化清单

### 4.0 本次落地状态

| 项目 | 当前实现 |
|---|---|
| 发布状态分离 | 已实现提交中、已提交、审核中、审核通过、驳回、下架、未知和明确失败状态 |
| 自动回查 | 已实现前端 30 秒轮询；任务、平台状态、质量响应、trace ID 与最后检查时间服务端持久化 |
| 发布幂等 | 已按工作区、批次、货号和草稿 ID 生成稳定幂等键；未知结果禁止盲目重发 |
| 合规门禁 | 已实现认证/合规声明的证据来源和有效期入口；声明无证据时阻止进入草稿 |
| 商品交易类型 | 已读取类目发布能力，支持询盘品/在线批发品选择，并与 FOB、阶梯价、SKU 定价联动校验 |
| 质量闭环 | 已保存并展示 Alibaba 返回的真实质量响应；不再使用本地估算冒充平台分数 |
| Schema 变化 | 正式发布前重新读取实时 Schema；必填项变化时停止提交并返回明确补填入口 |
| 运营审计 | 库存更新、商品更新和上下架操作已保存操作者、时间、请求结果与错误 |
| 服务端恢复 | 已按工作区和当前店铺保存安全快照，并与浏览器快照按更新时间恢复 |
| 图片预检 | 已检查格式、体积、分辨率、长宽比和疑似过度压缩，并区分阻断与建议 |

仍需依赖真实线上数据继续迭代的部分：Alibaba 不同类目返回的质量分结构映射、ERP 定时库存同步策略、复杂图片内容一致性识别，以及平台审核状态枚举的更多真实样本。这些不会再用猜测值实现。

### P0：正式发布可靠性

#### P0-1 发布状态与审核状态分离

现状：前端在正式发布接口返回成功后，将商品标记为“已发布”，批次记录可能直接显示“已通过”。

风险：接口成功只说明提交请求被接受，不能证明商品已通过 Alibaba 审核并正常展示。

目标状态机：

```text
草稿待发布 → 提交中 → 已提交/待审核 → 审核通过/展示中
                              ↘ 审核退回
                              ↘ 已下架
                              ↘ 状态未知
```

验收标准：

- “已提交”和“审核通过”使用不同状态和文案。
- 只有平台回查确认展示状态后，批次才显示“审核通过”。
- 审核退回原因保存到商品和批次记录，并提供修复入口。

#### P0-2 发布后自动回查

现状：商品详情和质量分接口存在，但正式发布后没有自动形成审核回查任务。

验收标准：

- 发布后按退避策略查询商品详情或列表状态。
- 页面刷新或服务重启后仍能继续回查。
- 超过等待时间后显示“审核中”或“状态未知”，不能误报成功。
- 记录最后查询时间、平台状态、trace ID 和失败原因。

#### P0-3 发布幂等和结果不确定处理

现状：网络超时、网关中断或响应丢失时，无法可靠判断 Alibaba 是否已创建商品。

风险：直接重试可能重复创建商品。

验收标准：

- 每次发布保存稳定业务请求标识、批次 ID、货号和草稿 ID。
- 明确区分“平台明确失败”和“请求结果未知”。
- 结果未知时先按草稿 ID、货号或批次信息回查，再允许重试。
- 重复点击和页面恢复不能产生第二个发布请求。

### P1：风险和运营闭环

#### P1-1 发布前合规门禁

- 增加禁限售商品提示和高风险类目提醒。
- 对标题、关键词和详情进行风险词提示，但不得用本地规则替代 Alibaba 最终审核。
- 对认证、商标、品牌授权、图片版权保存证据来源和有效期。
- 高风险字段缺少真实证明时阻止正式发布。

#### P1-2 显式选择商品交易类型

- 类目确认后明确显示“询盘品”或“在线批发下单品”。
- 若两种模式都支持，提供简单解释和系统建议，由商家确认。
- 根据商品类型只显示相应的价格、库存、阶梯价、交期和交易字段。

#### P1-3 产品质量分优化闭环

目标流程：

```text
查询质量分 → 展示扣分原因 → 定位对应字段 → 修改并重新提交 → 再次查询
```

验收标准：

- 发布后展示真实产品质量分，不能使用本地估算冒充平台分数。
- 质量问题能够定位到标题、关键词、图片、详情、属性或认证等模块。
- 优化动作保留修改前后记录。

#### P1-4 类目和 Schema 变化检测

- 定期确认已发布商品的叶子类目仍然有效。
- 发现类目迁移、删除或 Schema 新增必填字段时，生成待办任务。
- 长时间保存的草稿在发布前重新获取 Schema 并重新校验。

#### P1-5 库存、更新和上下架运营

- 建立库存定时同步、失败重试和异常告警。
- 商品更新、库存变更和上下架操作保留操作者、时间和平台响应。
- 明确区分本地状态、平台状态和 ERP 状态。

### P2：体验和协作增强

#### P2-1 服务端工作台恢复

- 当前浏览器端 IndexedDB/localStorage 恢复保留。
- 增加服务端批次快照，实现换设备恢复、多人协作和历史版本审计。
- 图片二进制与敏感凭据不得直接写入普通日志或不受控快照。

#### P2-2 图片质量预检

- 检查文件格式、大小、分辨率和长宽比。
- 提示模糊、主体占比过低、拼图、无关物体和图片内容不一致。
- 将提示分为“Alibaba 硬性阻断”和“质量优化建议”，避免过度阻止用户。

## 5. 建议实施顺序

1. 发布状态与审核状态分离。
2. 发布后自动回查和审核原因保存。
3. 发布幂等与结果未知恢复。
4. 发布前合规门禁。
5. 质量分优化闭环。
6. 商品类型选择、类目变化检测和库存运营闭环。
7. 服务端恢复和图片质量增强。

在前三项完成前，不建议把更多资源投入新增固定字段或扩展自动正式发布能力。
